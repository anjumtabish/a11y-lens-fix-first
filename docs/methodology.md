# Methodology and reproducibility

## Pipeline

1. Open each configured local page in a headless browser using Playwright.
2. Inject axe-core and run a full-document analysis.
3. Preserve raw engine output; include critical and serious violations in the fix-first index.
4. Group failing rules across pages and retain WCAG tags supplied by axe-core.
5. Rank rules by page fan-out first and impact second, so shared issues rise above local findings as in the paper's high-leverage discussion.
6. Capture annotated screenshots for nodes that can be highlighted.
7. Write raw JSON, per-page notes, grouped findings, and a summary report.

## Scope and limitations

The published study uses a six-page static CivicDesk demo with intentionally planted defects. It is an offline, author-owned corpus. It does not establish improved detection recall, production effectiveness, developer time savings, or full WCAG conformance. A controlled triage study and assistive-technology checks are future research directions identified in the preprint.

## Implementation status

This repository contains the author-maintained implementation of the pipeline described in the preprint. The included scan is generated by the current code. Any difference from the historical paper results should be documented and investigated rather than silently adjusted.

## Reproducibility record

Observed current-code run: 13 November 2026 (local run; generated timestamp is recorded in `paper/evidence/a11y-scan/summary.json`). Command: `npm run a11y:public`. Environment: Node.js 25.2.1, Playwright 1.56.1, Chromium 141.0.7390.37, and axe-core 4.10.3. The scan used a 1280×720 viewport, matching the embedded Home figure, and the local six-page demo with remote HTTP(S) requests blocked.

The observed fix-first result is 16 critical and 12 serious page-level rule hits (28 total), across seven unique rules. The page-level rule sets match Appendix B, including the `label` finding on both Settings and Profile. The four rules reported on all pages are button-name, meta-viewport, html-has-lang, and color-contrast. This output comparison shows matching counts and rule distribution; it does not establish that every execution detail is identical. All axe violations are preserved in each page's raw JSON; `pages.json` and `report.md` distinguish all violations from the critical/serious fix-first subset. Machine-specific absolute paths are removed from the published raw JSON.
