# A11y Lens: Fix-First Accessibility Reporting

The author-maintained implementation of the method described in the preprint **“Fix-First Accessibility Reporting: Clustering Automated Findings and Showing Them on the Page”** by Md Tabish Anjum.

**Preprint DOI:** https://doi.org/10.5281/zenodo.21873720

> **Implementation note:** This repository contains the current A11y Lens code and its rerunnable six-page study. The scan artifacts below are generated by this code; the preprint's historical results are documented separately from the current run.

## Research scope

- Playwright opens six local CivicDesk pages.
- axe-core runs against each page.
- The public demo scan blocks remote HTTP(S) requests.
- Critical and serious rule hits are retained for the fix-first index.
- Findings are clustered across pages by axe rule ID.
- WCAG tags are retained and common success-criterion tags are formatted for display.
- Rules affecting more pages rank first; impact breaks ties.
- Raw axe results, per-page summaries, cluster JSON, Markdown summary, and annotated screenshots are written to `paper/evidence/a11y-scan/`.

This is a reporting layer, not a new accessibility detection engine. Automated checks do not replace keyboard testing, screen-reader testing, or expert review, and a passing scan does not establish WCAG conformance.

## Requirements

- Node.js 20 or later
- npm
- Playwright Chromium browser

## Install

```bash
npm ci
npx playwright install chromium
```

## Run the public offline demo

```bash
npm run a11y:public
```

Output files:

```text
paper/evidence/a11y-scan/
├── summary.json
├── clusters.json
├── pages.json
├── report.md
├── home.axe.json
├── home.annotated.png
└── ... per-page files
```

The generated evidence is retained in the repository so the published comparison can be inspected. The saved raw axe JSON uses stable demo URLs instead of machine-specific absolute paths. The ignore rules exclude local dependencies, OS metadata, and transient Playwright output.

The scanner counts **rule hits per page**, not individual DOM nodes, when calculating the ticket-candidate ratio. The exact output can vary with browser, axe-core, markup, and rule behavior. Compare the generated report with the published preprint; do not edit output to force the historical counts.

## Current implementation run

The observed run on 13 November 2026 used Node.js 25.2.1, Playwright 1.56.1, Chromium 141.0.7390.37, and axe-core 4.10.3 with `npm run a11y:public` at a 1280×720 viewport. It found 16 critical and 12 serious page-level rule hits (28 total), across seven unique rules, matching the historical counts reported in the preprint. These are current results generated by this code, not copies of the 2026 scan output. Per-run versions and timestamp are recorded in `paper/evidence/a11y-scan/summary.json`; see [the methodology note](docs/methodology.md) for the reproducibility record.

## Demo corpus

| Page | Intentionally planted defect(s) described by the paper |
|---|---|
| Home | Shared header button name, viewport zoom restriction, missing document language, low contrast |
| Catalog | Shared header button name, viewport zoom restriction, missing document language, low contrast |
| Requests | Shared defects plus an unnamed select |
| Settings | Shared defects plus an unlabeled checkbox |
| Profile | Shared defects plus unlabeled form control and image without alt text |
| Help | Shared header button name, viewport zoom restriction, missing document language, low contrast |

The six-page corpus is a synthetic test fixture with planted defects. It is not a representative sample of production websites.

## Research provenance

The preprint reports a scan dated 5 August 2026 using axe-core 4.10: six pages, 16 critical rule hits, 12 serious rule hits, 28 total critical/serious page-level rule hits, and seven unique failing rules. Those are **historical results reported in the paper**; the separately recorded current run produces matching totals and rule distribution.
